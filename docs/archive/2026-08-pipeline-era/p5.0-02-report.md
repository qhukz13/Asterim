### `packages/shared/src/events.ts`

Four payload interfaces and four `AsterimEvent` aliases:

| Payload | Fields |
| :-- | :-- |
| `MemoryDecisionCreatedPayload` | `projectId`, `decision: ProjectDecision` |
| `MemoryDecisionSupersededPayload` | `projectId`, `decisionId`, `supersededBy`, `decision?: ProjectDecision` |
| `MemoryIntentUpdatedPayload` | `projectId`, `intent: ProjectIntent \| null`, `previousIntentId?` |
| `MemoryRuleCreatedPayload` | `projectId`, `rule: ArchitecturalRule` |

Aliases: `MemoryDecisionCreatedEvent`, `MemoryDecisionSupersededEvent`, `MemoryIntentUpdatedEvent`, `MemoryRuleCreatedEvent`.

Each payload declares `projectId: string` explicitly, following the `ContextUpdatedPayload` precedent rather than the older payloads that rely solely on the `AsterimEvent<T>` intersection (`payload: T & { projectId?: string; threadId?: string }`). This is compatible with that intersection and upgrades the field from optional to required — which matters, because P5.0-01 established that routing and filtering break when `projectId` is absent from a payload.

`MemoryDecisionSupersededPayload.decision` is optional so the event can carry the replacing decision when supersession and creation happen in one operation, without forcing a second round-trip. `MemoryIntentUpdatedPayload.intent` is nullable so archiving an intent without a replacement is expressible.

## 4. Design decisions and open questions

These are choices made in the absence of a specification. Each is cheap to reverse now and expensive after P5.0-03 writes rows.

**1. Two of the five evidence files named in the brief do not exist.** `docs/phase5-0-project-memory-core.md` and `docs/phase5-0-task-plan.md` are absent; `docs/pre-phase5-audit.md` contains no memory content. Field shapes were therefore derived from the brief plus P5.0-01 repository evidence, not from a design document. This compounds blocker #7 from P5.0-01: `blueprint/` still has no Project Memory entry, and in an Architecture-First repo a subsystem of this size needs a Change Proposal (`.agents/templates/CHANGE_PROPOSAL.md`) against `ARCHITECTURE.md`/`DOMAIN_MODEL.md` before implementation code lands.

**2. Timestamps are `number` (ms epoch), not ISO `string`.** The package is split on this: `types/workspace.ts` and `types/audit.ts` use `string`, while `ContextEntry` in `events.ts` uses `number`. I matched `ContextEntry`, because every table P5.0-01 verified (`sessions`, `approvals`, `context_entries`) stores `INTEGER` `Date.now()` values, and `number` avoids a serialization hop at the persistence boundary. Consequence: memory types differ from the workspace/audit convention at the REST boundary, so any client formatting these dates cannot reuse the workspace-side helpers.

**3. `supersededBy` is `string | null`, not `string?`.** The brief marked only `codeRefs?` as optional, implying `supersededBy` is required — but a non-superseded decision has no value for it. Required-and-explicitly-null honours the brief's requiredness while forcing writers to state the absence rather than omit it. Change to `supersededBy?: string` if the opposite reading was intended.

**4. `AgentWorkSummary.agentType` is `string`, not a union.** `AgentService` narrows locally to `'aider' | 'claude' | 'antigravity'`, but providers self-register into `globalProviderRegistry` and `packages/shared` exposes no agent-type union to reuse. `string` avoids baking a closed set into the contract that the registry is explicitly designed to extend.

**5. `ArchitecturalRule.scopePattern` is required.** The brief lists it non-optional, so project-wide rules need a sentinel; `'**'` is documented in the source as that convention. If project-wide is better expressed as absence, make it optional before rows exist.
