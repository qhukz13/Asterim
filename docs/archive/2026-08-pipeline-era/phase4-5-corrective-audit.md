# Asterim Marketing Website — Critical Corrective Visual & Experience Audit

**Audit Date**: August 11, 2026  
**Auditor**: Lead Product Designer, Creative Director & CTO  
**Target Application**: `@asterim/marketing` (`apps/marketing`)  

---

## 1. Executive Diagnostic — Why the Current Website Fails

While the Phase 4.5 website is technically functional and compiles cleanly, it **fails as a premium developer product experience**. It looks and feels like a generic AI/SaaS template generated by an AI assistant rather than a serious developer tool designed by a world-class product team.

### Root Causes Identified:
1. **"Widget Tunnel Vision"**: The site treats interactivity as a collection of tiny inspector cards, buttons that change text paragraphs, and decorative counters (`PID 4912`, `60 FPS / 16ms`, `RAM 42MB`). These metrics dominate the UI without communicating what using Asterim actually *feels* like.
2. **Card Container Overload**: Virtually every section wraps its content inside rounded dark rectangle boxes (`.surface-card`). This creates visual monotony, hides visual hierarchy, and destroys whitespace rhythm.
3. **Abstract Diagrams Over Real Product UI**: The hero section currently displays an abstract 4-step "Control Plane Architecture Topology" diagram instead of a large, beautiful, realistic composition of the actual Asterim Workstation interface (`apps/web`).
4. **Lack of a Cinematic Story Narrative**: The page reads like a feature list spreadsheet rather than a progressive visual story that guides a first-time developer from *terminal chaos* to *complete control plane governance*.
5. **Static Motion Language**: Animations are limited to basic hover transitions and string typewriter logs rather than stateful visual transitions (e.g., watching an agent call a tool, generate a diff, hit a security gate, wait for approval, and resume).

---

## 2. Detailed Audit Across 7 Quality Dimensions

### 1. Product Comprehension (Current Rating: 4/10)
- **Problem**: A developer visiting for 5 seconds sees a large text headline and a 4-node node inspector grid. They must read technical paragraphs to realize Asterim is a local desktop application that manages agent subprocesses.
- **Root Cause**: The product interface itself is hidden below the fold behind technical architecture diagrams.
- **Fix**: Place a large, realistic, beautiful composition of the **Asterim Workstation interface** directly in the hero.

### 2. Visual Hierarchy & Composition (Current Rating: 5/10)
- **Problem**: Monotonous layout rhythm. Every section follows the same formula: `section-tag` + `section-title` + `section-lead` + `3-column grid of rounded cards`.
- **Root Cause**: Over-reliance on `.surface-card` grid primitives.
- **Fix**: Remove container boxes from non-essential sections. Use open, typography-driven layouts, full-width product surfaces, and asymmetrical narrative blocks with generous whitespace.

### 3. Product Authenticity (Current Rating: 5/10)
- **Problem**: Demos rely on invented visual gadgets (e.g., "Control Plane Node Inspector", "Leak Risk 0%", "SIGTERM Cascading Active" pills) that do not exist in `apps/web`.
- **Root Cause**: Designing marketing widgets instead of rendering authentic `apps/web` product UI components (Environment Switcher, Session Sidebar, PTY Terminal, Changes/Diff View, Security Approval Modal).
- **Fix**: Reconstruct realistic product UI views strictly adhering to `apps/web` visual patterns and terminology.

### 4. Interaction Quality (Current Rating: 4/10)
- **Problem**: Interactions consist of clicking a button to replace a text string in a box. This feels cosmetic and artificial.
- **Fix**: Build an **Interactive Agent Workflow Experience** where the user actually watches an agent run, generate a real file diff, trigger a security approval modal, click `Approve Command`, and see execution complete.

### 5. Motion & Transition Quality (Current Rating: 3/10)
- **Problem**: Motion is almost entirely absent except for CSS hover shifts and string appends.
- **Fix**: Introduce stateful motion for step transitions, terminal output streams, diff reveals, environment scope switching, and scroll-driven section reveals.

### 6. Premium Product Polish (Current Rating: 5/10)
- **Problem**: Border overload (`border: 1px solid var(--border-subtle)` around every single container), bright green text glows, and dense micro-pills.
- **Fix**: Adopt a calm, expensive visual language: deep dark background (`#080c14`), subtle elevated surfaces (`#0f172a`), extremely restrained borders (`rgba(255,255,255,0.05)`), large refined typography (`Inter` / `JetBrains Mono`), and emerald `#10b981` strictly reserved for active execution states and primary CTAs.

### 7. Competitive Benchmark Analysis
- **Cursor / Raycast / Linear**: Render large, crisp, authentic product UI compositions with progressive disclosure. They don't fill the page with 15 tiny feature boxes—they let 2 or 3 large, flawless product visual compositions communicate quality.
- **Goal for Asterim**: Match this standard by eliminating widget noise and building a cinematic, product-first experience.
